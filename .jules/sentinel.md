## 2026-04-03 - Strict Validation on localStorage Numerics
**Learning:** `parseInt` and `parseFloat` can silently accept and evaluate partial or garbage strings to numbers, while `Number()` converts empty arrays `[]` or whitespaces `" "` to `0`. Both cases allow corrupted external payloads or invalid types from `localStorage` to pass unchecked into the game state, causing bugs.
**Action:** Enforced strict, explicit inline validation `(val !== null && val !== undefined && String(val).trim() !== '' && typeof val !== 'object' && !Array.isArray(val)) ? Number(val) : NaN` before parsing state properties (`currentScore`, `highScore`) and registry volumes (`sfxVolume`). Replaced all vulnerable `parseFloat` and single `Number()` usages in Desktop and Mobile state initialization.
